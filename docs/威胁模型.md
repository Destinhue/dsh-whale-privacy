# dsh-whale-privacy 威胁模型

> 目标不是“让模型永远不说错话”，而是让**私密事实在到达错误受众之前被一层独立的机制拦下**。模型可以犯错，插件不能替它猜。

## 1. 要保护什么

| 资产 | 典型位置 | 泄漏后的后果 |
| --- | --- | --- |
| 私聊内容与关系 | QQ/微信私聊 session、`memory/<peer>.json`、`persona.md` | 被群友/公众看到，关系破裂，人肉 |
| 长期记忆 | `~/.dsh`、插件自己的 memory 目录、向量库 | 一次群聊召回把几个月私聊倒出来 |
| 凭据 | `.credentials.yaml`、环境变量、Cookie（SESSDATA/bili_jct）、API Key | 账号被接管、被刷额度 |
| 本机路径与文件 | `/Users/<name>/...`、`~/.dsh/...` | 暴露真实身份、项目、其他客户资料 |
| 发布包 | release zip、promo、截图、录屏 | 把 `~/.dsh`、session、cookie 一起发给所有人 |

## 2. 泄漏路径（按真实插件形态）

### P1 记忆注入：私聊记忆被喂进群聊

最常见的一条。`dsh-self-improved`、`dsh-familiar-memory`、大肥鱼 Life 类插件都会在 `agent/pre-step` 或 system prompt 里注入“相关记忆”。如果召回只按语义相似度、不按会话受众过滤：

- 私聊里说“我住在朝阳区、电话 138…”，群聊里有人问“你住哪”，召回把整段注入；
- 模型不一定复述原文，但会用“你上次说的那个地址”暗示，甚至直接说全；
- 这类泄漏**不经过外发工具参数**，出站闸门看不到。

**本插件的边界**：`privacy_recall` 只返回当前受众允许的事实；`tools/pre-execute` 只能拦外发工具。它**不能**阻止另一个插件直接往 system prompt 里塞私聊记忆——那需要记忆插件自己调用 `whalePrivacy.recall({audience})`，或把本插件作为唯一召回入口。README 里明确写了这条集成契约。

### P2 会话复用：同一个 session 服务两个受众

QQ 群聊和私聊如果共用一个 session，历史里的私聊内容会自然进入群聊上下文，任何闸门都来不及。`dsh-qqbot` 用 `qqbot:${appId}:${scope}:${peerId}` 派生 session 是正确的；自己写 bot 时最容易省掉 `peerId`。

**本插件**：不创建 session；在本文 §5 要求“一个受众一个 session”，并建议用 `session/event` 做审计。

### P3 工具结果夹带：读文件/跑命令把 token 带进群

`shell` 输出 `.env`、`read_file` 读 `.credentials.yaml`、`web_fetch` 返回带 `SESSDATA` 的 URL；随后模型把结果贴进群。`tools/post-execute` 是最后一道能改结果的地方。

**本插件**：对工具结果做 secret/path/PII 脱敏（默认 `secrets`），审计只记类别，不记原文。局限：只改 `content` 里的 text block，`value`/附件/图片 OCR 不处理。

### P4 模型改写：没有原词，仍有语义

闸门按**精确短语**匹配私密词。模型可以把“朝阳区”改写成“东边那个区”，把电话拆成“一三八…”。这不是本插件能完全解决的；它降低“直接贴原文”的概率，不承诺语义级 DLP。

**建议**：对高敏事实，`privacy_remember` 同时登记多个别名/缩写；发布前人工复核。

### P5 跨插件直连：绕过工具层

插件可以直接读 `~/.dsh`、直接 `fetch`、直接写文件，不经过 `tools/*`。`dsh-mask` 和本插件都只能覆盖自己挂的钩子。

**建议**：把“外发”收敛到少量工具（QQ/B站/邮件/webhook），其他插件不要自己发；发布前用 `grep` 扫 `SESSDATA|sk-|/Users/`。

### P6 发布/打包：把运行态一起发出去

`dafeiyu-hub` 的“去隐私版”说明这是真实发生过的：仓库里带 `memory/`、cookie、关系档案、绝对路径。`promo/` 里的截图也可能带真实昵称/群名。

**本插件**：vault 用 AES-256-GCM 加密，`audit.jsonl` 不存正文；但 `~/.dsh/sessions/*.zstd` 仍是明文，发布脚本必须显式排除。

### P7 日志与审计：审计本身成为泄漏源

如果审计记录原文，等于把秘密复制一份。本插件只记录 `{seq,ts,event,tool,audience,decision,reasons,hash,prev}`，`reasons` 也只放类别/数量。

### P8 Agent 间转交：子 agent 不知道受众

主 agent 把“用户私聊摘要”交给子 agent 做研究，子 agent 再写进公开报告。`send_message`/`subagents` 也是外发通道。

**建议**：本插件默认把 `*send*message*` 当 outbound；子 agent 任务描述里不要放私密原文，放 `privacy_recall` 的 id 或脱敏摘要。

### P9 平台侧与截图

群聊里的图片、语音、文件、引用回复、撤回前缓存，平台侧都留痕。插件只能控制“发什么”，控制不了“对方截图”。

## 3. 严重度矩阵

| 路径 | 触发难度 | 影响 | 现有覆盖 | 建议 |
| --- | --- | --- | --- | --- |
| P1 记忆注入群聊 | 高（默认行为） | 极高 | 本插件召回隔离 + 外发闸门 | 记忆插件改为调用 `whalePrivacy.recall` |
| P2 session 复用 | 中 | 极高 | 无（需部署约束） | 一受众一 session |
| P3 工具结果夹带 | 高 | 高 | post-execute 脱敏 | 再加发布前扫描 |
| P4 语义改写 | 中 | 高 | 部分（精确词） | 多别名 + 人工复核 |
| P5 跨插件直连 | 中 | 高 | 无 | 收敛外发工具 |
| P6 发布包 | 高 | 极高 | vault 加密 | 发布脚本排除 sessions/memory |
| P7 审计泄漏 | 低 | 中 | 本插件不存正文 | 定期轮转 |
| P8 子 agent | 中 | 中 | 默认扫描 send_message | 任务描述脱敏 |
| P9 平台截图 | 高 | 中 | 无 | 告知用户 |

## 4. 本插件做什么、不做什么

**做**：

- 从 tool call 参数推断受众（`group_id`/`peer_id`/`comment`），不信任模型自述；
- 对群聊/公开/未知受众拦截：私密短语、PII（可配）、本机路径、密钥；
- 私聊只拦密钥/路径，私密短语放行；
- 加密、按 audience/scope 的私密记忆库；
- 工具结果 secret/path 脱敏；
- 哈希链审计，不存正文；
- system prompt 注入隐私行为规则。

**不做**：

- 不创建/隔离 session（部署责任）；
- 不阻止其他插件直接注入 system prompt；
- 不做语义级 DLP、图片 OCR、附件内容检查；
- 不保证平台侧不留痕；
- 不替代磁盘加密与发布前人工审计。

## 5. 部署检查表

1. 每个群/每个私聊独立 session key，禁止跨受众复用。
2. 只让本插件做记忆召回；其他记忆插件改为 `ctx.get('whalePrivacy').recall({audience,scope})`。
3. 外发工具命名带平台/受众（`qq_send_group_message`、`bili_comment`），否则受众推断会落到 `unknown`。
4. `cordis.patch.yml` 里把 `pii` 调到 `block`（默认 `warn`，避免误伤）。
5. 发布前：`grep -R "SESSDATA\|sk-\|/Users/\|DSH_HOME"`，排除 `sessions/`、`memory/`、`.credentials.yaml`。
6. 定期 `privacy_status` 看 audit chain 是否 `OK`。
